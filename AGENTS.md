# agents

Builds the rules section of a repo's `AGENTS.md` from parts in `catalog.yaml`. See the README for layout.

## Commands

```
go test ./...
go run . path/to/repo
```

Generated by agents. Run it again to change these rules.

## Supervision: reviewed

A human reviews every change before it is committed.

- Edit freely in the working tree.
- Do not commit or push until asked. Propose a commit message; a human writes or approves it.
- Confirm before opening or changing issues, PRs or comments.
- Never merge.

## Code

- Understanding comes before features. Whoever maintains the code must be able to understand every line.
- Keep it small and simple. Solve the problem at hand, not a general version of it.
- Nothing speculative: no stubs, empty modules, or abstractions without a current use.
- Comment only what the code cannot say itself, as a short, precise claim. No narration or history.
- Every behavior change comes with a test that fails without it.

## Modularity

- Each package or module has one clear responsibility.
- No needless layers: no interfaces, wrappers or packages with a single caller or implementation.
- A little duplication beats the wrong abstraction. Extract shared code on its third use.

## Libraries

- Use the standard library first. Add a library only when it clearly earns its place.

## Writing

- Docs, commit messages and PR descriptions are plain and concise. No marketing or filler.

## Git

- One logical change per commit. The history should read as a series of intentional steps.
- No WIP or fixup commits. Squash them before pushing.
- Write the subject in the imperative, 72 characters or fewer. Add a body only to explain why.
- No AI attribution: no `Co-Authored-By` trailers or "generated by" lines in commits, PRs or issues.

## Controls

- Stay within the task. Report unrelated problems instead of fixing them.
- When requirements are unclear, ask instead of guessing.
- Run the repo's checks before reporting work as done, and report failures as they are.
- Never delete branches or files outside the task, force-push, or rewrite published history without asking.
- Never read, print or commit secrets: `.env` files, keys, tokens, credentials.
